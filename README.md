# ФизКвест

Веб-приложение для офлайн-квеста школьников на Дне физики.

Участник сканирует QR-код на входе, вводит имя и получает на телефон личный маршрут по станциям и свой ArUco-маркер. На станции начальник наводит камеру на группу из 10–15 человек, и всем сразу засчитывается прохождение. На финише проверяют, всё ли пройдено, и выдают приз.

Кому телефон не подходит, получает заранее напечатанный бумажный маркер. Такой участник проходит станции в любом порядке и может посмотреть свой прогресс на экране помощи.

Рассчитано на 500 участников: маркеры № 0–249 бумажные, № 250–999 выдаются телефонам.

## Роли и экраны

| Кто | Адрес | Что делает |
|---|---|---|
| Участник | `/` | Вводит имя. Внизу три вкладки: **Список** станций в порядке его маршрута, **Код** (свой маркер), **Карта** (текущая станция пульсирует). Когда станцию засчитали, телефон вибрирует и на станции появляется галочка. |
| Начальник станции | `/staff` → PIN станций | Выбирает свою станцию и жмёт «Сканировать». Камера распознаёт сразу все маркеры в кадре. Рамка у маркера: зелёная — засчитано, серая — уже было, красная — неизвестный маркер. Если пропала связь, сканы копятся в очереди и отправляются, когда связь вернётся. |
| Выдача призов | `/staff` → PIN призов | Сканирует маркер и видит, всё ли пройдено. Жмёт «Выдать приз». Если не всё пройдено, можно «Выдать всё равно»: выдача запишется в журнал. Второй раз приз не выдаётся. |
| Экран помощи | `/staff` → PIN помощи | Ноутбук с камерой постоянно распознаёт маркеры. Для маркера в кадре справа показываются пройденные станции и карта. Нужен в основном участникам с бумажными маркерами. |
| Администратор | `/staff` → PIN админа | Дашборд в реальном времени. Станции: добавить, изменить, отключить, передвинуть на карте. Участники: таблица активных, карточка, ручные отметки, QR для переноса на другой телефон. Настройки: PIN-коды, закрытие регистрации, сброс. Печать бумажных маркеров. |

Все сотрудники входят через одну страницу `/staff`, роль определяется введённым PIN.

PIN-коды по умолчанию (**поменяйте перед мероприятием**):

| Роль | PIN |
|---|---|
| Администратор | `0987` |
| Начальники станций | `111111` |
| Выдача призов | `222222` |
| Экран помощи | `333333` |

## Стек

- **Backend**: Django 5, Django REST Framework, Django Channels (WebSocket) под uvicorn; PostgreSQL 16; Redis 7 (channel layer и кэш).
- **Frontend**: React, TypeScript, Vite, CSS Modules. Маркеры распознаёт OpenCV.js (ArUco, словарь `DICT_5X5_1000`) в Web Worker прямо в браузере. На сервер уходят только номера маркеров.
- **Инфраструктура**: Docker Compose. В проде контейнер `web` (nginx) раздаёт фронтенд и проксирует API на backend. TLS делает nginx на хосте.

```
браузер ──HTTPS──▶ nginx на хосте (TLS) ──▶ web :8080 (nginx) ──┬─ /api, /ws, /django-admin ──▶ backend (uvicorn)
                                                                 └─ всё остальное ─▶ статика React
backend ──▶ postgres
        └─▶ redis
```

Подробности архитектуры и доменных правил описаны в [CLAUDE.md](CLAUDE.md).

## Локальная разработка

Нужны Docker и Docker Compose v2.

```bash
docker compose -f docker-compose.dev.yml up --build
```

- Фронтенд: http://localhost:5173. Изменения в коде подхватываются на лету.
- Бэкенд: http://localhost:8000, uvicorn с `--reload`.
- Django-админка: http://localhost:5173/django-admin/, логин `admin`, пароль `admin`.
- При старте бэкенд сам применяет миграции и создаёт финиш, PIN-коды и 250 бумажных маркеров.

**Проверка камеры с телефона.** Браузер открывает камеру только по HTTPS или на `localhost`. Чтобы сканировать с телефона в той же Wi-Fi-сети, запустите фронтенд с самоподписанным сертификатом:

```bash
DEV_HTTPS=1 docker compose -f docker-compose.dev.yml up
# на телефоне откройте https://<IP-ноутбука>:5173 и примите предупреждение о сертификате
```

Если у вашего пользователя нет доступа к Docker (`permission denied … docker.sock`):

```bash
sudo usermod -aG docker $USER   # затем перелогиньтесь или выполните: newgrp docker
```

## Деплой на сервер

### 1. Сервер

- VPS на Ubuntu 22.04/24.04, **1 vCPU / 2 ГБ RAM** достаточно для 500 участников, 2 vCPU / 4 ГБ дают запас.
- Домен, A-запись которого указывает на IP сервера (например `quest.example.com`).
- Открытые порты 80 и 443.

```bash
# Docker (официальный скрипт)
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER && newgrp docker

# nginx и certbot на хосте
sudo apt update && sudo apt install -y nginx certbot python3-certbot-nginx git
```

### 2. Код и настройки

```bash
git clone <URL репозитория> physquest && cd physquest
cp .env.example .env
```

Заполните `.env`:

| Переменная | Что указать |
|---|---|
| `DJANGO_SECRET_KEY` | Длинная случайная строка: `openssl rand -hex 32` |
| `DJANGO_ALLOWED_HOSTS` | Ваш домен + `localhost,127.0.0.1,backend` |
| `DJANGO_CSRF_TRUSTED_ORIGINS` | `https://ваш-домен` |
| `DJANGO_SUPERUSER_USERNAME` / `_PASSWORD` | Логин и пароль Django-админки (`/django-admin/`, для отладки) |
| `POSTGRES_PASSWORD` | Случайный пароль: `openssl rand -hex 16` |
| `UVICORN_WORKERS` | 2 (при 2+ vCPU можно 3–4) |
| `DB_POOL_MAX` | Соединений с БД на воркер. `UVICORN_WORKERS × DB_POOL_MAX` должно быть меньше 100 |
| `WEB_PORT` | Порт на `127.0.0.1`, куда проксирует nginx хоста (по умолчанию 8080) |

### 3. Запуск

```bash
docker compose up -d --build
docker compose ps                         # все 4 сервиса должны быть Up
curl -s localhost:8080/api/public/status  # {"registration_open":true}
```

Первая сборка идёт несколько минут. Во фронтенд-образ входит OpenCV.js (13 МБ, после сжатия 3,7 МБ).

### 4. nginx и HTTPS на хосте

```bash
sudo cp deploy/nginx.host.conf.example /etc/nginx/sites-available/physquest
sudo sed -i 's/quest.example.com/ваш-домен/g' /etc/nginx/sites-available/physquest
sudo ln -s /etc/nginx/sites-available/physquest /etc/nginx/sites-enabled/
```

Сертификата ещё нет, поэтому сначала выпустите его. Временно закомментируйте блок `server { listen 443 … }`, затем:

```bash
sudo nginx -t && sudo systemctl reload nginx
sudo certbot --nginx -d ваш-домен
# верните блок 443, проверьте и перезагрузите
sudo nginx -t && sudo systemctl reload nginx
```

В конфиге три важные настройки, без них не работают вебсокеты и ограничение попыток ввода PIN:
- `Upgrade`/`Connection` для WebSocket;
- `proxy_read_timeout 3600s`;
- `X-Forwarded-For $remote_addr` (именно перезапись, а не дописывание).

Проверка: откройте `https://ваш-домен` с телефона, должна появиться форма «Как тебя зовут?».

## Подготовка к мероприятию

1. **Войдите в админку**: `https://ваш-домен/staff` с PIN `0987`.
2. **Настройки → PIN-коды**: задайте свои коды, 4–8 цифр, у каждой роли разные. Раздайте их: начальникам станций, выдаче призов, экрану помощи.
3. **Станции и карта**: добавьте станции (номер, название, короткое описание, которое видит участник) и перетащите метки на карту. Финиш уже создан, его нужно только поставить на место.
4. **Печать маркеров**: распечатайте бумажные маркеры, лучше все 250 (63 листа A4, по 4 маркера на листе). Нужна печать 100% («Фактический размер»), без масштабирования.
5. **QR-код на вход**: сделайте в любом генераторе QR-код со ссылкой `https://ваш-домен/`, распечатайте крупно и повесьте у входа.
6. **Репетиция**:
   - зарегистрируйтесь с 2–3 телефонов;
   - отсканируйте их на станции;
   - выдайте приз;
   - проверьте экран помощи с бумажным маркером.
7. **Настройки → Сброс квеста** (нужен PIN админа): удаляет участников и отметки. Станции, карта и PIN-коды сохраняются.

**Устройства сотрудников.** Нужен телефон с нормальной камерой и Chrome или Safari. Заранее, по хорошему Wi-Fi, откройте на нём страницу станции и дождитесь «✓ Распознавание готово». После этого OpenCV.js закэширован, и в день мероприятия камера открывается сразу.

**Экран помощи.** Ноутбук с веб-камерой (или внешней камерой), браузер на весь экран (F11).

## В день мероприятия

- **Дашборд** (Обзор): сколько участников, сколько прошли всё и сколько получили приз. По каждой станции видно, сколько человек идёт на неё сейчас.
- **Станция отключилась** (ведущий ушёл): Станции → «Отключить». Станция пропадёт из маршрутов и из условия «прошёл всё», уже поставленные отметки останутся.
- **Новая станция**: добавьте её в админке. Тем, кто ещё в пути, она встанет в маршрут в случайное место среди непройденных.
- **Участник сменил или потерял телефон**: Участники → найти по номеру → QR «Перенос на другой телефон». Если телефона нет совсем, дайте бумажный маркер.
- **Отметка не прошла** или поставлена по ошибке: Участники → карточка → «Отметить» / «Снять».
- **Конец регистрации**: Настройки → «Закрыть регистрацию».
- **Мигает «нет связи» на станции**: сканировать можно дальше. Сканы сохраняются в телефоне («в очереди: N») и уйдут, когда появится связь. Не закрывайте вкладку, пока очередь не опустеет.

## Обслуживание

### Обновление

```bash
cd physquest
git pull
docker compose up -d --build
```

Миграции применяются автоматически при старте backend. Активные вебсокеты переподключатся сами за несколько секунд.

### Бэкап и восстановление

```bash
# бэкап
docker compose exec -T postgres pg_dump --clean --if-exists -U physquest physquest > backup-$(date +%F-%H%M).sql

# восстановление (затирает текущие данные!)
docker compose exec -T postgres psql -U physquest -d physquest < backup.sql
```

В день мероприятия стоит делать бэкап перед началом и после окончания.

### Логи и состояние

```bash
docker compose ps
docker compose logs -f backend     # API, вебсокеты, время обработки сканов
docker compose logs -f web         # nginx внутри compose
docker compose restart backend
```

### Полная остановка

```bash
docker compose down        # данные в томе pgdata сохраняются
docker compose down -v     # УДАЛИТЬ всё, включая базу
```

## Тесты

```bash
# тесты бэкенда (37+): маршруты, повторные сканы, призы, PIN, вебсокеты
docker compose -f docker-compose.dev.yml exec backend pytest

# тесты фронтенда: отрисовка маркеров сверяется с OpenCV
cd frontend && npm install && npm test

# проверка типов
cd frontend && npm run typecheck
```

### Нагрузочный тест

Имитирует 500 участников на вебсокетах и 10 станций, которые сканируют группы по 15 человек. Измеряет, за сколько отметка доходит до телефона.

> ⚠️ Тест **сбрасывает данные квеста** и добавляет станции «LT N». Запускайте только на тестовом стенде.

```bash
docker compose -f docker-compose.dev.yml exec backend python loadtest/run.py --base http://localhost:8000
```

Ориентир (прод-сборка, 2 воркера, ноутбук): 5000 отметок за ~9 с, скан группы p95 ≈ 120 мс, доставка на телефон p95 ≈ 180 мс.

## Как поменять карту

Карта — это [frontend/src/map/building.svg](frontend/src/map/building.svg). Два этажа в виде перевёрнутой «П»: сверху первый с входом, ниже второй. Форма этажа описана один раз в `<defs>` и используется для обоих этажей.

- Подписи, двери, лестницы и прочее можно дорисовывать прямо в SVG. Координаты станций хранятся в долях от размера карты, поэтому такие правки их не сдвигают.
- **Размер `viewBox` (1000×1400) лучше не менять.** Если всё же пришлось, поменяйте `MAP_WIDTH`/`MAP_HEIGHT` в [QuestMap.tsx](frontend/src/map/QuestMap.tsx) и напишите миграцию координат станций, как в `backend/quest/migrations/0002_two_floor_map.py`.
- После правки пересоберите: `docker compose up -d --build web`.

## Частые проблемы

| Симптом | Причина и решение |
|---|---|
| «Камера недоступна» на странице станции | Сайт открыт не по HTTPS. Проверьте сертификат. В dev используйте `DEV_HTTPS=1`. |
| «Нет доступа к камере» | Браузеру запрещена камера: настройки сайта → Камера → Разрешить. |
| Долго висит «Загрузка распознавания…» | Первая загрузка OpenCV.js (3,7 МБ) при плохом интернете. Откройте страницу заранее по Wi-Fi. |
| Вебсокеты всё время переподключаются, «нет связи» | В nginx хоста нет `Upgrade`/`Connection` или мал `proxy_read_timeout`. Сверьтесь с `deploy/nginx.host.conf.example`. |
| В логах `Timeout reading from redis` или `Too many connections` | Сломаны настройки Redis в `CHANNEL_LAYERS` (`socket_timeout`, `max_connections`) в `backend/config/settings.py`. Их нельзя убирать: без них redis-py 8+ рвёт соединения. |
| `remaining connection slots are reserved` от Postgres | `UVICORN_WORKERS × DB_POOL_MAX` ≥ 100. Уменьшите `DB_POOL_MAX`. |
| 400 Bad Request на всех страницах | Домена нет в `DJANGO_ALLOWED_HOSTS`. |
| Маркер плохо читается с телефона | Яркость экрана на максимум, без бликов, расстояние 0,5–2 м. Если не помогает — бумажный маркер. |
| «Слишком много попыток» при входе | 10 неверных PIN за минуту с одного IP. Подождите минуту. |
